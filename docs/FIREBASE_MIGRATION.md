# INK.OS — переход на Firebase Spark

## Что уже есть в приложении

Текущий `www/index.html` хранит записи локально: IndexedDB (`inkos_db`, версия 4) и резервный localStorage (`inkos_fallback_db`). В этой версии не найдено активного подключения к Supabase. Поэтому перенос нельзя безопасно выполнить одной заменой URL сервера: облачная авторизация и синхронизация должны быть добавлены отдельно.

## Бесплатная инфраструктура

- Firebase Authentication — вход по электронной почте и паролю.
- Cloud Firestore — синхронизация данных между устройствами.
- Firebase Hosting — публикация веб-версии.
- Firebase Storage — только если потребуется облачное хранение изображений и файлов.

Использование бесплатного тарифа зависит от текущих квот Google; это не гарантия неограниченной работы.

## Структура облачных данных

Все данные пользователя должны находиться под его UID:

`users/{uid}/records/{recordId}`

В поле `store` сохраняется имя локального хранилища INK.OS (например, `clients`, `events`, `finance`, `settings`). Это сохраняет разделение данных мастеров. Нельзя использовать общий публичный список записей или полагаться только на фильтрацию в интерфейсе.

## Важные этапы

1. Создать Firebase project на тарифе Spark и веб-приложение.
2. Включить Email/Password в Authentication.
3. Создать Firestore database и опубликовать `firestore.rules`.
4. Настроить Storage только при необходимости.
5. Подключить SDK и добавить вход/регистрацию в интерфейс.
6. Добавить двустороннюю синхронизацию всех локальных хранилищ, включая settings, backups, consents и фотографии.
7. Добавить явные действия «Выгрузить резервную копию» и «Восстановить резервную копию».
8. Проверить вход двух разных аккаунтов и убедиться, что данные не пересекаются.
9. Проверить перенос на тестовом аккаунте, затем публиковать.

## Защита данных при миграции

- Не удалять локальную IndexedDB и не очищать старый сервер до проверки резервной копии.
- Сначала загружать записи в облако с сохранением исходных ID, затем проверять количество записей и выборочно сверять содержимое.
- Не переносить PIN-код, токены, пароли или секреты в общедоступные документы.
- Настройки и данные согласий/подписей требуют особой осторожности.
- Firebase web config сам по себе не является серверным секретом, но безопасность обеспечивают Authentication и Security Rules.

## Публикация

В корне репозитория добавлен `firebase.json` с папкой `www` как каталогом публикации. Перед развёртыванием нужно привязать реальный project ID через Firebase CLI. Плейсхолдеры конфигурации намеренно не используются: выдуманный ID не позволит подключиться к проекту.

## Текущий статус

Это безопасный инфраструктурный каркас, а не завершённый перенос. Облачная авторизация, синхронизация и развёртывание требуют реального Firebase project config и последующей проверки.
